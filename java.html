Java는 커피 이름이 아니라, 컴퓨터에게 일을 부탁하는 언어예요.
처음엔 모든 문법을 외우려고 하지 않아도 괜찮아요. 코드를 읽을 때 “무엇을 저장하지?”, “언제 실행하지?”, “누가 이 일을 맡지?”라고 질문하면 길이 보입니다.

첫 번째 미션 · 오늘의 버그 탐정

계산기는 왜 7이 아니라 34를 보여 줬을까요?

친구가 숫자 3과 4를 입력했더니 프로그램이 34라고 답했어요. 컴퓨터가 산수를 못한 게 아니라, 입력을 숫자가 아닌 글자 두 개로 이해했을 수 있어요.

추리 질문 데이터의 모양(자료형)이 달라지면 같은 + 기호도 다르게 동작할까요?

단서와 풀이 보기

맞아요. 숫자 3 + 4 는 덧셈이지만, 문자열 "3" + "4" 는 글자를 이어 붙여 "34" 가 됩니다. 자바에서는 값이 어떤 종류인지 자료형으로 구분해요. 그래서 변수와 자료형부터 차근차근 살펴봅니다.

01

자바와 프로그램: 컴퓨터에게 일을 시키는 방법

프로그램은 컴퓨터가 따라 할 수 있도록 적어 둔 명령의 묶음 이에요. Java(자바)는 사람이 비교적 읽기 쉬운 형태로 명령을 작성하도록 만든 프로그래밍 언어입니다.

컴퓨터는 코드를 그냥 읽을 수 있나요?

사람이 쓰는 Java 코드를 컴퓨터가 바로 실행하는 것은 아니에요. 개발 도구가 코드를 검사하고 바이트코드라는 중간 형태로 바꾸면, JVM(자바 가상 머신)이 그 코드를 실행합니다. 덕분에 같은 바이트코드를 여러 운영체제에서 실행할 수 있어요.

첫 만남 · 화면에 인사하기
public class Hello {
    public static void main(String[] args) {
        System.out.println("안녕, Java!");
    }
}

System.out.println 은 괄호 안의 내용을 화면에 출력하라는 명령이에요. 문장 끝의 세미콜론 ; 은 “이 명령은 여기서 끝”이라는 표시입니다.

① 작성 Hello.java
사람이 읽는 코드
→
② 컴파일 javac
문법 검사·변환
→
③ 바이트코드 Hello.class
중간 코드
→
④ 실행 JVM
명령 수행
이름 쉽게 말하면 하는 일
JDK 자바 개발 도구 상자 코드 작성·컴파일·실행에 필요한 도구를 제공해요.
컴파일러 번역기 겸 문법 검사기 Java 소스 코드를 바이트코드로 바꿔요.
JVM 바이트코드를 실행하는 가상 컴퓨터 운영체제에 맞게 자바 프로그램을 실행해요.

기억 포인트 소스 코드(.java) → 컴파일 → 바이트코드(.class) → JVM 실행. 개발할 때는 보통 JDK를 설치합니다.

02

값과 변수: 데이터에 이름표 붙이기

프로그램은 숫자, 문자, 참/거짓 같은 값 을 기억하고 활용해요. 변수는 값을 담아 두고 다시 부를 수 있게 이름표를 붙인 공간입니다. 서랍에 “점수”라고 라벨을 붙여 두는 모습과 비슷해요.

변수 상자
이름 score
←
값 95
변수 만들기
int score = 95;
String nickname = "민지";
boolean isReady = true;

예: int 는 정수형, String 은 문자열, boolean 은 참 또는 거짓이에요. = 는 수학의 “같다”가 아니라 오른쪽 값을 왼쪽 변수에 넣는 대입 기호입니다.

자료형은 값의 종류를 알려 줘요

종류를 알면 허용되는 계산과 필요한 저장 공간을 정할 수 있습니다. 처음에는 자주 쓰는 것부터 익혀도 충분해요.

자료형 담는 값 예시 처음 만나는 쓰임
int 정수 int age = 20; 나이, 개수
double 소수점 숫자 double rate = 0.15; 비율, 평균
boolean 참 또는 거짓 boolean open = false; 조건 판단
char 문자 하나 char grade = 'A'; 한 글자 기호
String 문자열 String name = "하늘"; 이름, 문장

형 변환: 값의 옷 갈아입기

정수를 실수로 바꾸는 것처럼 자료형을 바꾸는 일을 형 변환 이라고 해요. 작은 범위의 정수를 더 넓은 실수 범위에 넣을 때는 자동 변환되기도 하지만, 실수를 정수로 바꾸면 소수점 아래가 사라질 수 있어요.

double price = 12;       // 12가 12.0으로 자동 변환
int count = (int) 3.9;   // 소수점 아래가 잘려서 3
03

조건과 반복: 상황에 따라 고르고, 같은 일을 되풀이하기

조건문은 갈림길이에요

if 는 조건이 참인지 확인하고, 참일 때 실행할 일을 고릅니다. else 는 그렇지 않을 때의 선택지예요.

비가 오면 우산 챙기기
boolean raining = true;

if (raining) {
    System.out.println("우산을 챙겨요");
} else {
    System.out.println("가볍게 나가요");
}
비가 오나요?
참 ↓ 거짓 ↓
우산 챙기기 가볍게 나가기

비교할 때는 == (같다), != (다르다), > (크다), && (그리고), || (또는) 같은 연산자를 사용해요. 대입 = 과 비교 == 을 구분하는 게 중요합니다.

반복문은 지루한 일을 대신해요

같은 명령을 여러 번 써야 한다면 반복문에게 맡깁니다. for 는 반복 횟수를 알고 있을 때, while 은 조건이 참인 동안 반복할 때 자주 사용해요.

1부터 3까지 세기
for (int i = 1; i <= 3; i++) {
    System.out.println(i);
}

int i = 1 에서 시작해, i <= 3 인 동안 실행하고, 한 번 실행할 때마다 i++ 로 1씩 늘려요. 출력은 1, 2, 3입니다.

문법 스스로 물어볼 질문 실수 방지 팁
if 어떤 조건에서 실행할까? 조건을 괄호 () 안에 써요.
for 몇 번 반복할까? 시작값, 종료 조건, 증가식을 확인해요.
while 언제까지 반복할까? 조건이 계속 참이면 무한 반복이 될 수 있어요.
30초 확인

위 for 문에서 조건을 i < 3 으로 바꾸면 몇까지 출력될까요? 정답은 1과 2예요. 반복을 시작하기 전에 조건을 먼저 확인하기 때문입니다.

04

메서드와 배열: 일을 나누고 여러 값을 묶기

메서드는 이름 붙인 작업이에요

계산이나 출력을 여기저기서 반복한다면, 일의 절차를 메서드로 묶어 이름을 붙일 수 있어요. 입력을 받아 처리하고 결과를 돌려주는 작은 기계라고 생각해 보세요.

입력값 → 메서드
정해 둔 일 수행 → 반환값
두 숫자의 합을 반환하는 메서드
static int add(int a, int b) {
    return a + b;
}

int result = add(3, 4); // result에는 7
부분 뜻 예시
매개변수 메서드가 받을 입력 int a, int b
반환형 돌려줄 결과의 종류 int
return 결과를 돌려주고 메서드 종료 return a + b;
void 돌려줄 결과가 없음 화면에 출력만 하는 메서드

배열은 같은 종류의 여러 값을 줄 세워요

점수를 다섯 개 저장하는데 변수 이름을 다섯 개 만들지 않고, 배열 한 개에 차례대로 담을 수 있어요. 칸 번호는 인덱스 라고 부르고, 첫 칸의 번호는 0입니다.

인덱스 0 80
인덱스 1 95
인덱스 2 72
인덱스 3 88 
int[] scores = {80, 95, 72, 88};
System.out.println(scores[0]); // 80
System.out.println(scores.length); // 4

존재하지 않는 칸(예: 길이가 4인 배열의 scores[4] )에 접근하면 오류가 납니다. 칸 번호가 0부터 시작한다는 점을 꼭 기억하세요.

05

클래스와 객체: 나만의 데이터 설계도 만들기

프로그램이 커지면 값과 기능을 서로 관련 있는 것끼리 묶고 싶어요. 클래스 는 객체를 만드는 설계도, 객체 는 그 설계도로 실제 만든 대상입니다. 설계도로 자동차 여러 대를 만들 수 있는 것과 같아요.

설계도 · 클래스 Profile 이름, 점수 인사하기()
만들기 →
실제 객체 · 인스턴스 minjiProfile 이름 = "민지" 점수 = 95
설계도에서 객체 만들기
class Profile {
    String name;
    int score;

    void introduce() {
        System.out.println("안녕하세요, " + name + "입니다");
    }
}

Profile user = new Profile(); // 객체 생성
user.name = "민지";
user.introduce();

new 는 설계도를 바탕으로 새 객체를 만들라는 표현입니다. 객체 안에 들어 있는 값은 필드 , 객체가 할 수 있는 동작은 메서드 라고 불러요.

캡슐화: 안쪽을 보호하고 필요한 문만 열기

점수 필드를 아무나 바꾸게 두면 150점이나 -10점도 들어올 수 있어요. 필드를 private 으로 감추고, 검사하는 메서드를 통해서만 바꾸게 하는 것을 캡슐화 라고 합니다.

class Score {
    private int value;

    public void setValue(int value) {
        if (value >= 0 && value <= 100) {
            this.value = value;
        }
    }

    public int getValue() {
        return value;
    }
}

this.value 는 현재 객체가 가진 value 필드를 가리켜요. 모든 필드에 무조건 getter/setter를 만드는 것이 정답은 아니며, 객체가 지켜야 할 규칙을 분명히 하는 것이 핵심입니다.

06

상속과 인터페이스: 공통점을 재사용하고 약속을 나누기

상속은 공통 기능을 물려받아요

extends 로 부모 클래스의 공통 기능을 자식 클래스가 이어받을 수 있습니다. 예를 들어 모든 동물이 이름을 가진다는 공통점을 부모에 두고, 고양이와 강아지의 구체적인 행동을 자식에 둘 수 있어요.

Animal · 공통 기능
Cat · 야옹 Dog · 멍멍
“고양이는 동물이다”처럼 정말로 ~이다 관계일 때 상속이 자연스러워요.

인터페이스는 할 수 있는 일의 약속이에요

인터페이스는 “이 기능을 제공하는 객체라면 이 메서드를 갖춰 주세요”라고 정하는 약속입니다. 여러 종류의 객체가 같은 역할을 서로 다른 방식으로 할 수 있어요.

interface Printable {
    void print();
}

class Photo implements Printable {
    public void print() {
        System.out.println("사진 인쇄");
    }
}

다형성 은 같은 약속(인터페이스)을 바라보더라도 실제 객체에 따라 동작이 달라지는 성질이에요. 호출하는 쪽은 세부 구현을 몰라도 print() 를 부탁할 수 있습니다.

개념 쉽게 설명하면 기억할 점
상속 공통된 기능을 물려받기 자식이 부모의 한 종류인지 생각해요.
인터페이스 기능을 제공하겠다는 약속 구현 세부보다 할 수 있는 일을 표현해요.
다형성 같은 요청, 객체마다 다른 동작 호출하는 코드와 구체 구현을 느슨하게 연결해요.

초보 팁 상속을 많이 쓰는 것이 목표는 아니에요. 공통 역할은 인터페이스로 표현하고, 객체 간 조립(구성)을 사용하는 편이 더 단순한 경우도 많습니다.

07

예외와 패키지: 문제가 생겼을 때, 파일이 많아졌을 때

예외는 실행 중 발견한 문제예요

없는 파일을 열거나 숫자를 0으로 나누는 등 실행 중 문제가 생기면 예외가 발생할 수 있어요. 프로그램이 갑자기 끝나지 않도록 try 에서 시도하고 catch 에서 대응할 수 있습니다.

try {
    int number = Integer.parseInt("abc");
    System.out.println(number);
} catch (NumberFormatException e) {
    System.out.println("숫자로 바꿀 수 없는 입력이에요");
}

"abc" 는 숫자로 바꿀 수 없어서 예외가 생겨요. 예외를 무조건 잡아 숨기기보다, 복구할 수 있는 방법을 안내하거나 적절한 곳에서 처리해야 합니다.

패키지는 클래스의 주소이자 정리함이에요

클래스가 많아지면 비슷한 역할끼리 폴더처럼 묶어요. 패키지 이름은 클래스의 위치를 구분하고, import 는 다른 패키지의 클래스를 코드에서 짧은 이름으로 사용하도록 도와줍니다.

package study.greeting;

import java.util.Scanner;
문제 상황 예시 생각할 대응
입력 형식이 잘못됨 문자를 정수로 변환 사용자에게 올바른 입력을 안내
찾는 데이터가 없음 파일·목록에서 항목 검색 없을 때의 기본 동작을 정함
프로그램 내부 오류 예상하지 못한 상태 기록을 남기고 원인을 조사
08

컬렉션과 제네릭: 여러 데이터를 목적에 맞게 담기

배열은 크기를 처음 정하면 바꾸기 어렵습니다. 데이터가 늘거나 줄 수 있다면 컬렉션을 쓰면 편해요. 자바 컬렉션은 데이터를 담고 찾고 꺼내기 위한 자료구조 도구입니다.

List 줄 세우기

순서가 있고 중복을 허용해요.
예: 대기 순서, 장바구니

Set 중복 없이 모으기

같은 값을 한 번만 보관해요.
예: 참석자 명단

Map 열쇠로 찾기

키와 값을 짝지어요.
예: 아이디 → 사용자

이름 목록에 추가하고 읽기
List<String> names = new ArrayList<>();
names.add("민지");
names.add("하늘");
System.out.println(names.get(0)); // 민지

List<String> 의 <String> 은 이 목록에는 문자열을 담겠다는 표시예요.

제네릭은 담을 수 있는 종류를 미리 정해요

제네릭은 클래스나 메서드가 다룰 데이터 종류를 사용하는 곳에서 지정하게 해요. 잘못된 종류의 값이 섞이는 것을 컴파일 단계에서 발견할 수 있고, 꺼낸 값을 다시 변환하는 수고도 줄어요.

컬렉션 데이터 모양 자주 쓰는 동작
List<T> 순서 있는 목록 add , get , remove
Set<T> 중복 없는 모음 add , contains
Map<K,V> 키와 값의 짝 put , get , containsKey

여기서 T , K , V 는 종류를 표시하는 자리표시자예요. 실제로는 String , Integer 같은 타입을 넣습니다.

람다와 스트림: 목록을 간결하게 다루기

조금 뒤에 만나도 괜찮아요

기초 문법이 익숙해진 뒤에 읽어도 괜찮은 주제예요. 람다식은 짧은 작업을 간결하게 표현하는 문법이고, 스트림은 컬렉션의 데이터를 조건에 따라 고르고 변환해 결과로 모으는 흐름입니다.

점수에서 합격자만 골라 이름 목록 만들기
List<String> passed = students.stream()
    .filter(student -> student.getScore() >= 60)
    .map(student -> student.getName())
    .toList();

filter 는 조건에 맞는 학생을 고르고, map 은 학생을 이름으로 바꿔요. 화살표 -> 뒤에 실행할 동작을 적습니다.

전체 학생 → filter 60점 이상 → map 이름만 모은 목록

더 알아보기

equals와 hashCode는 함께 맞춰야 해요

참조형에서 ==는 같은 객체인지 비교하고, equals()는 정한 값 비교 규칙을 사용합니다.

문자열 비교
String first = new String("java");
String second = new String("java");
System.out.println(first == second);      // false
System.out.println(first.equals(second)); // true

HashMap과 HashSet은 hashCode로 후보 위치를 찾고 equals로 같은 키인지 판별합니다. equals가 같다고 보는 객체는 같은 hashCode를 반환해야 해요. 저장된 키 객체가 바뀌면 조회에 실패할 수 있으므로 값 객체는 불변으로 두는 편이 안전합니다.

컬렉션 선택 순서가 필요하면 List, 중복을 막으면 Set, 키로 찾으면 Map을 검토하세요.

심화

객체의 수명과 값 비교 규칙

도달할 수 없는 객체는 회수 대상이에요

객체는 보통 힙에 생성되고 변수에는 객체를 가리키는 참조가 들어갑니다. 더 이상 도달할 수 없는 객체는 가비지 컬렉터가 회수할 수 있지만 파일·소켓 같은 외부 자원은 자동 메모리 회수에만 맡기지 마세요. try-with-resources로 사용 후 닫고, 캐시와 컬렉션이 객체를 불필요하게 오래 잡아 두는지도 살핍니다.

equals와 hashCode 계약을 함께 맞춰요

값 기준으로 equals를 재정의했다면 같은 값의 객체가 같은 hashCode를 반환해야 HashMap과 HashSet에서 올바르게 찾을 수 있습니다. 생성 뒤 상태가 바뀌지 않는 불변 객체는 여러 코드에서 공유하기 쉽고 동시성 문제도 줄여 줍니다.

  • null 가능성을 분명히 하고 필요한 경우 명시적으로 검사합니다.
  • 컬렉션은 순서, 중복 허용, 키 조회 요구에 맞춰 고릅니다.
  • 예외를 처리했다면 복구하거나 원인을 보존해 전달합니다.
