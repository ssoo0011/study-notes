프론트엔드는 사용자가 보고 조작하는 영역이에요.
서버가 화면을 전부 그려 보내는 방식도 있고, 브라우저가 API에서 데이터를 받아 화면을 구성하는 방식도 있어요. 두 방식 모두 웹의 기본을 공유합니다.

01

브라우저와 웹: 주소를 받아 문서를 보여 주는 프로그램

브라우저는 주소를 해석하고, 서버에서 문서와 파일을 받아 화면으로 표시해요. HTML은 문서 구조, CSS는 시각적 표현, JavaScript는 사용자 반응과 데이터 처리를 담당합니다.

주소를 입력하면

  1. 도메인에 해당하는 서버 주소를 찾습니다.
  2. 서버와 연결하고 HTTP 요청을 보냅니다.
  3. 응답으로 HTML, CSS, JavaScript, 이미지 등을 받습니다.
  4. 브라우저가 파일을 해석하고 화면을 그립니다.
  5. 사용자 동작에 따라 추가 요청을 보낼 수 있습니다.
주소 입력브라우저 → 서버 요청HTTP → 파일 응답HTML·CSS·JS → 화면 표시브라우저 렌더링

브라우저 개발자 도구의 Network 탭은 요청 주소, 상태 코드, 응답 크기와 시간을 보여 줘서 웹 문제를 찾을 때 자주 사용합니다.

02

HTML: 콘텐츠의 의미와 문서 구조

HTML은 화면에 보이는 글자를 단순히 나열하는 것이 아니라 제목, 문단, 링크, 이미지, 폼 같은 의미를 표시해요. 태그는 요소의 종류를 나타내고, 속성은 추가 정보를 제공합니다.

가장 작은 HTML 문서 모양
<main>
  <h1>오늘의 글</h1>
  <p>여기에 설명을 씁니다.</p>
  <a href="/posts/1">글 읽기</a>
</main>

모양보다 의미가 먼저인 시맨틱 HTML

<header> , <nav> , <main> , <article> 처럼 목적이 드러나는 태그를 쓰면 보조 기술과 검색 엔진, 다른 개발자가 문서 구조를 이해하기 쉬워집니다.

요소 용도 기억할 점
h1 ~h6 제목 단계 크기 꾸미기보다 문서 계층 표현
a 다른 주소로 이동 실제 목적지 href 제공
button 현재 화면에서 동작 수행 이동 링크와 버튼 역할 구분
label 입력창 이름 연결 키보드·스크린 리더 사용자 지원
03

CSS: 요소의 모양과 배치를 정하기

CSS 규칙은 어떤 요소를 꾸밀지 선택자(selector)로 고르고, 중괄호 안에 색·크기·간격 같은 선언을 적어요.

클래스가 note인 요소에 스타일 주기
.note {
  color: #334466;
  padding: 1rem;
  border-radius: 0.5rem;
}

브라우저는 콘텐츠를 상자처럼 배치합니다. 기본적으로 각 요소에는 콘텐츠, 안쪽 여백(padding), 테두리(border), 바깥 여백(margin)이 있어요.

Flexbox와 Grid

도구 잘 맞는 상황 예
Flexbox 한 방향으로 나열·정렬 메뉴 항목, 버튼 줄
Grid 행과 열을 함께 배치 카드 목록, 페이지 격자
Media Query 화면 조건에 따라 규칙 변경 모바일에서 한 열로 바꾸기

색상이나 크기만으로 상태를 전달하지 말고 글자·아이콘도 활용하세요. 작은 화면에서도 콘텐츠가 읽히는지 직접 확인하는 것이 중요합니다.

04

JavaScript: 화면을 움직이고 입력에 반응하기

JavaScript는 브라우저에서 실행되어 버튼 클릭, 입력 검사, 화면 변경, 서버 요청 등을 처리할 수 있어요. 변수에 상태를 저장하고 함수로 동작을 묶으며 조건과 반복으로 흐름을 제어합니다.

DOM과 이벤트

DOM은 브라우저가 HTML 문서를 객체 구조로 표현한 것입니다. JavaScript가 DOM을 찾아 내용을 바꾸거나 이벤트 처리 함수를 연결할 수 있어요.

버튼을 누르면 문구 바꾸기
const button = document.querySelector("#hello");
button.addEventListener("click", () => {
  document.querySelector("#message").textContent = "반가워요!";
});

사용자 입력은 늘 예상과 다를 수 있어요. 브라우저 검사만 믿지 말고 서버에서도 입력을 검증해야 합니다. 클라이언트 코드는 사용자가 확인하거나 바꿀 수 있기 때문이에요.

05

서버와 연결: fetch로 API 요청하기

브라우저에서 서버 API를 호출해 JSON 데이터를 받을 수 있어요. fetch 는 네트워크 요청을 보내고 응답을 기다리는 비동기 API입니다.

데이터 가져오기 · 실패 응답도 확인해야 해요
async function loadPosts() {
  const response = await fetch("/api/posts");
  if (!response.ok) throw new Error("요청 실패");
  const posts = await response.json();
  return posts;
}

JSON 데이터

JSON은 객체와 배열처럼 보이는 텍스트 형식으로 데이터를 주고받는 데 널리 사용돼요. 날짜, 숫자, 누락된 값 등이 양쪽 언어에서 어떻게 해석되는지 API 계약을 정하는 것이 중요합니다.

응답 상황 예시 화면에서 할 일
성공 200 + 데이터 결과 표시
로그인 필요 401 로그인 안내
데이터 없음 404 빈 결과 안내
서버 문제 500 재시도·오류 안내
06

접근성과 반응형: 누구나 다양한 화면에서 쓰기

접근성은 장애나 기기·환경에 관계없이 서비스를 이용할 수 있게 만드는 성질이에요. 의미 있는 HTML, 키보드로 조작 가능한 인터랙션, 입력 설명과 오류 안내, 충분한 색 대비가 도움이 됩니다.

화면 크기에 맞게 배치 바꾸기

반응형 디자인은 휴대폰·태블릿·컴퓨터 화면 크기 등에 따라 읽기 쉬운 배치로 조정하는 방식입니다. 특정 기기 너비를 외우기보다 콘텐츠가 자연스럽게 보이는지 확인하세요.

확인 항목 초보 점검 방법
키보드 조작 Tab·Enter·Space만으로 주요 기능 사용
입력 이름 각 입력창에 연결된 label이 있는지
이미지 설명 정보 이미지에 대체 텍스트가 있는지
작은 화면 가로 스크롤 없이 글과 버튼이 보이는지

브라우저는 DOM을 만들고 이벤트에 반응해요

브라우저는 HTML에서 DOM 트리를 만들고 CSS를 계산해 요소를 배치합니다. JavaScript 이벤트 처리기는 클릭·키 입력을 받아 화면이나 데이터를 갱신합니다.

클릭 이벤트 처리
const button = document.querySelector("#count");
let count = 0;
button.addEventListener("click", () => {
  count += 1;
  button.textContent = "클릭 " + count + "회";
});

시간이 걸리는 네트워크 요청은 비동기로 처리해 화면이 멈추지 않게 합니다. 응답을 받은 뒤 상태를 갱신하고 실패 상태도 사용자에게 알려야 해요.

접근성 버튼은 키보드로 작동하고 목적을 설명하는 이름이 있어야 합니다. 입력에는 레이블을 연결하고 색상만으로 상태를 전달하지 마세요.

심화

비동기 화면과 접근 가능한 폼 만들기

브라우저 검증은 서버 검증을 대신하지 않아요

필수 입력과 형식을 브라우저에서 안내하면 사용성이 좋아지지만 요청을 직접 보내면 검증을 우회할 수 있습니다. 서버도 값을 검증하고 오류가 난 필드와 이유를 알려 주세요. label을 입력 요소에 연결하고 오류 메시지를 보조 기술이 읽도록 하면 키보드·화면 읽기 사용자도 문제를 찾기 쉽습니다.

비동기 요청에는 로딩·실패·경쟁 상태가 있어요

요청 중에는 로딩을 표시하고 성공·실패 뒤 화면을 갱신합니다. 검색어를 빠르게 바꾸면 오래된 응답이 최신 결과를 덮을 수 있어 AbortController로 취소하거나 요청 순서를 확인하세요. 네트워크 실패와 빈 결과도 정상적인 화면 상태로 다룹니다.

  • 서버 문자열을 HTML로 그대로 삽입하지 않습니다.
  • 키보드 포커스와 색상 대비를 확인합니다.
  • 작은 화면에서도 콘텐츠 순서와 조작이 유지되도록 합니다.
