01

비트와 바이트: 컴퓨터가 다루는 가장 작은 표기

컴퓨터 내부 데이터는 전기 신호의 두 상태를 바탕으로 표현해요. 이 한 자리를 비트(bit) 라고 하고, 보통 8비트를 묶어 바이트(byte) 라고 부릅니다. 비트들을 조합해 숫자, 문자, 이미지 같은 정보를 표현해요.

2진수와 10진수
2진수 00000101 = 10진수 5
8비트 한 묶음 = 1바이트
1바이트로 표현 가능한 서로 다른 패턴 = 256가지

숫자·문자·파일도 결국 약속된 데이터

비트만 보면 그 자체로 글자나 사진이라는 뜻은 없어요. 어떤 문자 인코딩을 쓸지, 파일 형식이 무엇인지 약속을 알아야 바르게 해석할 수 있습니다. UTF-8은 웹에서 널리 쓰이는 문자 인코딩 중 하나예요.

종류 어떻게 표현하나? 개발 중 만나는 곳
정수 비트 패턴에 부호·범위 규칙 적용 정수 오버플로
실수 정해진 정밀도의 근삿값 소수 비교 오차
문자 문자와 숫자를 연결한 인코딩 깨진 한글·잘못된 인코딩
이미지·음성 파일 형식에 맞춘 픽셀·샘플 정보 디코딩·압축
02

CPU와 메모리: 명령을 읽고 값을 꺼내 실행해요

CPU는 프로그램의 명령을 실행하는 장치예요. 계산뿐 아니라 메모리에서 명령과 데이터를 읽고, 결과를 다시 기록합니다. 메모리(RAM)는 실행 중인 프로그램이 빠르게 읽고 쓰는 작업 공간이에요.

저장 장치프로그램 파일 → 불러오기 메모리실행 중인 코드·값 ↔ CPU명령 실행

메모리에는 빠르기와 크기의 층이 있어요

CPU 안의 레지스터와 캐시는 매우 빠르고 작아요. RAM은 더 크지만 전원이 꺼지면 내용을 잃고, SSD는 더 오래 보관하지만 RAM보다 느립니다. 자주 쓰는 데이터를 가까운 빠른 저장소에 두는 이유입니다.

저장 공간 특징 일상 비유
레지스터·캐시 매우 빠르고 용량이 작음 손에 들고 있는 메모
RAM 실행 중 빠르게 접근, 휘발성 책상 위 작업 공간
SSD·디스크 비교적 크고 전원이 꺼져도 보존 서랍과 파일 캐비닛

프로그램이 너무 많은 메모리를 사용하면 시스템이 느려지거나 종료될 수 있어요. 메모리 누수는 더 이상 필요하지 않은 메모리를 프로그램이 계속 붙잡고 놓지 않는 문제입니다.

03

운영체제: 프로그램과 하드웨어 사이의 관리자

운영체제(OS)는 CPU·메모리·파일·네트워크 같은 자원을 프로그램들이 사용할 수 있게 관리해요. Windows, macOS, Linux가 운영체제의 예입니다.

실행 중인 프로그램을 프로세스 라고 부르고, 프로세스 안에서 실행되는 작업의 흐름을 스레드 라고 해요. 하나의 프로세스에 여러 스레드가 있을 수 있습니다.

파일, 권한, 시스템 호출

프로그램은 운영체제의 기능을 통해 파일을 읽고, 네트워크 연결을 만들고, 새 메모리를 요청해요. 운영체제에 서비스를 요청하는 경계를 시스템 호출이라고 합니다. 사용자 계정과 권한은 어떤 자원에 접근할지 제한합니다.

개념 설명 개발에서 만나는 예
프로세스 운영체제가 관리하는 실행 프로그램 서버 앱 프로세스 확인
스레드 프로세스 안에서 실행되는 흐름 동시에 요청 처리
파일 디스크립터 열린 파일·소켓 등을 가리키는 번호 열린 연결이 너무 많음
권한 사용자·프로그램의 접근 범위 파일 접근 거부
04

동시성: 여러 작업이 겹쳐 진행될 때

동시성은 여러 일을 번갈아 처리해 동시에 진행되는 것처럼 보이게 하는 방식이고, 병렬성은 여러 CPU 코어 등이 실제 같은 시점에 일을 수행하는 것을 말해요. 동시에 작업한다고 언제나 더 빨라지는 것은 아닙니다.

여러 스레드가 같은 값을 읽고 수정하면 실행 순서에 따라 결과가 달라지는 경쟁 상태가 생길 수 있어요. 예를 들어 두 요청이 동시에 재고 1개를 읽고 각각 주문을 승인하면 재고가 잘못 처리될 수 있습니다.

공유 데이터는 규칙을 정해 다뤄요

문제 무슨 일이 생기나? 대응 아이디어
경쟁 상태 실행 순서에 따라 결과가 달라짐 공유 변경을 동기화·원자 처리
교착 상태 서로 상대가 가진 자원을 기다려 멈춤 자원 획득 순서와 범위를 단순화
기아 특정 작업이 자원을 오래 받지 못함 공정한 스케줄링·제한 시간 고려

동시성 버그는 매번 재현되지 않을 수 있어요. 공유 상태를 줄이고, 원자적 연산이나 동기화 도구를 알맞게 사용하며, 실제 다중 요청 테스트도 필요합니다.

05

저장 장치와 성능: 느린 곳이 전체를 기다리게 해요

CPU 계산은 빠르지만 디스크나 네트워크 응답은 상대적으로 오래 걸릴 수 있어요. 앱이 데이터베이스 응답을 기다리는 시간이 길면 CPU가 한가해도 요청 전체는 느릴 수 있습니다. 성능을 고치려면 먼저 어디에서 시간이 쓰이는지 측정해야 해요.

캐시와 병목

캐시는 다시 사용할 가능성이 높은 결과를 잠시 저장해 더 빨리 제공하는 방식이에요. 원본 데이터가 바뀌면 캐시가 오래된 값을 줄 수 있으므로 만료·갱신 규칙도 필요합니다. 병목은 시스템 처리 속도를 가장 크게 제한하는 지점이에요.

프로세스와 메모리는 함께 움직여요

운영체제는 프로그램을 프로세스로 실행하며 코드·스택·힙 같은 메모리와 실행 상태를 관리합니다. 함수 호출 정보와 지역 값은 보통 스택에, 실행 중 동적으로 만든 데이터는 힙에 놓일 수 있어요.

RAM은 빠른 작업 공간이지만 전원이 꺼지면 내용이 사라지고, SSD는 상대적으로 느려도 파일을 보존합니다. CPU가 바쁘지 않아도 디스크나 네트워크를 기다리면 프로그램은 느릴 수 있으므로 자원별 대기를 나눠 살펴보세요.

프로세스와 스레드는 메모리를 나누어 써요

프로세스는 실행 중인 프로그램의 주소 공간과 자원 묶음이고, 스레드는 명령을 실행하는 흐름입니다. 같은 프로세스의 스레드는 메모리를 공유할 수 있어요. 여러 흐름이 같은 값을 동시에 바꾸면 경쟁 상태가 생기므로 잠금이나 메시지 전달로 접근 규칙을 정합니다. 잠금 순서가 꼬이면 교착 상태가 생길 수 있습니다.

가상 메모리와 캐시는 속도 차이를 감춰요

프로그램은 가상 주소를 사용하고 운영체제와 하드웨어가 실제 메모리와 연결합니다. 가까운 주소를 순서대로 읽으면 캐시 효율이 높아집니다. 반면 연결 리스트처럼 메모리를 흩어 다니면 느려질 수 있어요. 디스크와 네트워크 대기는 CPU 연산과 다른 병목이므로 각각 구분해 측정해야 합니다.

  • 병목을 측정한 뒤 최적화합니다.
  • CPU·메모리·디스크·네트워크 사용량을 나누어 봅니다.
  • 공유 데이터에 대한 동시 접근 규칙을 기록합니다.
