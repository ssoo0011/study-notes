자료구조와 알고리즘

🧩

처음부터 가장 빠른 풀이를 떠올리지 못해도 괜찮아요.
먼저 작은 예제로 정확한 답을 만드는 방법을 찾고, 입력 크기가 커질 때 느려지는 지점을 살펴 개선합니다.

01

문제를 작은 단계로 나누기

알고리즘 문제를 읽으면 먼저 입력, 원하는 출력, 규칙, 예외를 분리해요. 예제 두세 개를 손으로 풀면 숨어 있는 조건을 찾을 수 있습니다.

  1. 문제를 내 말로 다시 설명합니다.
  2. 입력과 결과의 자료형·범위를 확인합니다.
  3. 작은 예제와 경계값을 손으로 풉니다.
  4. 가장 단순하고 정확한 풀이를 작성합니다.
  5. 큰 입력에서 시간과 메모리가 충분한지 확인합니다.

Big O: 입력이 커질 때 얼마나 늘어날까?

Big O 표기법은 입력 크기 n이 커질 때 작업량이 어떻게 증가하는지 대략 표현해요. 실제 실행 시간은 컴퓨터와 데이터에 따라 다르지만, 풀이의 증가 추세를 비교하는 데 도움이 됩니다.

복잡도 이름 느낌 예
O(1) 상수 입력 크기에 거의 영향 없음 배열의 인덱스로 한 칸 읽기
O(log n) 로그 단계마다 범위를 크게 줄임 정렬된 자료의 이진 탐색
O(n) 선형 한 번 훑기 최댓값 찾기
O(n log n) 선형 로그 효율적인 일반 정렬 병합 정렬의 시간
O(n²) 제곱 모든 쌍을 비교하면 빠르게 커짐 이중 반복문
02

배열과 목록: 순서가 있는 데이터를 담기

배열은 여러 값을 순서대로 저장하고 인덱스로 빠르게 접근해요. 보통 크기가 고정되어 있습니다. List는 데이터를 추가하거나 제거하기 편한 목록 인터페이스로, 내부 구현에 따라 성능이 달라질 수 있어요.

index 0 첫 값
→
index 1 다음 값
→
index 2 그 다음
→
… 순서 유지
작업 배열·ArrayList에서 생각할 점
인덱스로 접근 빠름 유효 범위는 0부터 크기-1
끝에 추가 보통 빠름 내부 확장 시 복사가 생길 수 있음
중간 삽입·삭제 뒤 원소 이동 필요 자주 하는 작업인지 검토
값 찾기 순서대로 보면 O(n) 정렬 여부와 다른 구조 검토
03

탐색과 정렬: 찾기 쉬운 순서 만들기

선형 탐색은 처음부터 끝까지 확인해요. 정렬된 목록에서는 중간 값을 기준으로 범위를 반씩 줄이는 이진 탐색을 사용할 수 있습니다. 대신 이진 탐색은 데이터가 정렬되어 있어야 해요.

정렬은 값을 일정한 규칙으로 나열하기

정렬에는 비교 횟수뿐 아니라 안정성, 메모리 사용량, 데이터의 기존 순서 보존 같은 성질도 있어요. 실무에서는 직접 정렬 알고리즘을 구현하기보다 표준 라이브러리를 사용하고, 정렬 기준을 명확히 하는 경우가 많습니다.

방법 전제 대략적인 시간
선형 탐색 정렬 불필요 O(n)
이진 탐색 정렬된 데이터 O(log n)
단순한 이중 반복 정렬 작은 예제 학습에 적합 O(n²)
표준 라이브러리 정렬 비교 기준을 제공 대체로 O(n log n)
04

자료구조: 작업 방식에 맞는 그릇 고르기

같은 데이터라도 어떤 순서로 넣고 꺼낼지에 따라 알맞은 구조가 달라요. 데이터를 자주 추가하는지, 중복이 필요한지, 키로 바로 찾고 싶은지를 기준으로 고릅니다.

Stack과 Queue

Stack은 마지막에 넣은 것을 먼저 꺼내는 LIFO 구조예요. 접시 더미처럼 가장 위의 접시를 먼저 꺼냅니다. Queue는 먼저 들어온 것을 먼저 처리하는 FIFO 구조로, 줄 서기와 비슷해요.

Set과 Map

구조 규칙 실생활 예 Java 예
Stack 나중에 넣은 값부터 꺼냄 되돌리기 이력 Deque
Queue 먼저 온 값을 먼저 꺼냄 작업 대기열 Queue
Set 중복 없는 값 모음 유일한 태그 목록 HashSet
Map 키로 값을 찾음 회원 ID로 회원 조회 HashMap
05

트리와 그래프: 계층과 관계 표현하기

트리는 위아래 계층 구조를 표현해요. 파일 폴더, 조직도, HTML 요소 구조가 예입니다. 그래프는 여러 정점이 간선으로 연결된 구조로 도로망, 친구 관계, 서비스 간 의존을 표현할 수 있습니다.

너비 우선 탐색과 깊이 우선 탐색

너비 우선 탐색(BFS)은 가까운 이웃부터 넓게 살펴보고, 깊이 우선 탐색(DFS)은 한 경로를 따라 깊게 들어간 뒤 돌아옵니다. BFS는 보통 Queue, DFS는 재귀나 Stack으로 구현할 수 있어요.

문제 자주 쓰는 구조·방법 예
가장 적은 간선 수의 경로 가중치 없는 그래프 BFS 미로의 최단 이동 수
모든 연결 구역 세기 DFS 또는 BFS 섬의 개수
계층의 부모·자식 찾기 트리 순회 폴더 구조
가중치가 있는 최단 거리 다익스트라 등 도로 거리

알고리즘을 고를 때는 그래프가 방향이 있는지, 간선에 비용이 있는지, 사이클이 가능한지 확인해야 합니다.

06

재귀와 문제 풀이 습관

재귀는 함수가 더 작은 입력의 자기 자신을 호출하는 방식이에요. 반드시 끝나는 기저 조건이 있어야 합니다. 입력이 줄어들지 않거나 기저 조건이 빠지면 무한 호출과 스택 오류가 날 수 있어요.

막힐 때 사용할 풀이 루틴

  1. 문제 설명을 한 문장으로 바꾸고 입력 범위를 표시합니다.
  2. 작은 입력을 직접 풀어 규칙과 예외를 찾습니다.
  3. 자료구조와 단순한 알고리즘을 먼저 선택합니다.
  4. 정확성을 작은 테스트로 확인합니다.
  5. 복잡도를 계산하고 꼭 필요한 부분을 개선합니다.

입력 크기 제한은 어떤 복잡도가 가능한지 알려 주는 힌트예요. 어려운 기법부터 끼워 맞추기보다 정확한 풀이를 만든 뒤 점진적으로 개선하는 습관이 중요합니다.

입력 크기가 커질 때 작업량 비교하기

시간 복잡도는 초 단위 실행 시간이 아니라 입력 크기 n에 따라 작업량이 커지는 모양을 나타냅니다. n이 1,000일 때 O(log n)은 약 10단계, O(n)은 최대 1,000회, O(n²)은 약 1,000,000회 수준일 수 있어요.

복잡도예시조건

O(n)선형 탐색전체 확인
O(n²)모든 쌍 비교중첩 반복

Big O만으로 고르지 말고 입력 크기와 정렬 여부, 갱신 빈도, 메모리 사용을 함께 고려하세요. 반복 횟수와 반복 안의 작업량을 따로 적으면 분석하기 쉽습니다.

심화

문제 구조에 맞는 탐색과 최적화

이진 탐색은 구간의 규칙을 지켜요

정렬된 배열에서 중간값을 확인하고 탐색 범위를 절반씩 줄입니다. 반복할 때마다 정답이 구간 안에 있다는 조건을 유지하고, [low, high)처럼 오른쪽 끝을 제외하는 구간을 쓰면 경계 계산이 분명해집니다. 빈 배열, 값이 맨 앞이나 맨 뒤에 있는 경우, 중복 값이 있는 경우를 직접 추적해 보세요.

동적 계획법과 그리디를 구분해요

동적 계획법은 작은 문제의 답을 저장해 중복 계산을 줄입니다. 상태·점화식·초기값·계산 순서를 먼저 정하세요. 그리디는 매 순간의 선택이 전체 최적해로 이어진다는 근거가 있어야 하므로 반례를 찾아 확인해야 합니다.

  • 입력 크기와 시간·메모리 제한부터 확인합니다.
  • 반복 횟수뿐 아니라 반복 안의 작업량도 셉니다.
  • 작은 입력으로 정답을 손으로 계산해 비교합니다.
